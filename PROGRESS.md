## Known gaps / notes

- Local dev uses **SeaweedFS** instead of MinIO: MinIO stopped publishing container images in 2025 (owner decision, 2026-10-19). Production remains AWS S3 / Cloudflare R2.
- Use `127.0.0.1`, not `localhost`, in local connection URLs: on Windows `localhost` resolves to IPv6 first and psycopg stalls until timeout.
- Two DB aliases: `default` = `billing_app_login` (all queries, RLS applies), `owner` = `billing_owner` (migrations only). `manage.py migrate` without `--database=owner` fails with "permission denied for table django_migrations" by design.
- Tests: `default` mirrors `owner`; `tests/conftest.py` overrides `django_db_setup` so the owner alias always gets a `test_` database (pytest-django alone would leave the mirror pointing at the real dev database).
- Tests needing real COMMITs use the `committed_db` fixture (no TRUNCATE flush; fresh tenant ids per test; the test DB is dropped at session end).
- **Auth items deferred** (need a schema decision): per-tenant / plan quotas (only per-user and per-IP rate limits exist), `Idempotency-Key` on signup (`idempotency_keys` requires a tenant and user, which do not exist yet at signup), HaveIBeenPwned check (Django's common-password list is used for now), sliding vs absolute session lifetime (sliding 30 days now).
- Invitations: the member invite still answers `422 no_account` for an unknown email (it tells an OWNER/ADMIN whether an email is registered); the web then offers an invitation by email. Expired / accepted / withdrawn email invitations are kept (no purge yet).
- Signup reveals whether an email is registered (`422 email_taken`); login and reset do not. Revisit with email verification (send a "you already have an account" email instead).
- Email: plain-text messages only; production needs a transactional SMTP provider (`EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`) with SPF / DKIM on the sending domain, and `APP_BASE_URL` set to the web app. Accounts created before migration `accounts/0003` are unverified and cannot issue until they confirm (use "Send a new link"). Without a running worker (and without `CELERY_TASK_ALWAYS_EAGER=true`) emails wait in Redis.
- Documents: cess is not exposed on lines yet (no stored cess rate); a document with a project must bill the project's client.
- Tax engine: reverse-charge documents and real invoices checked by a CA are still to do; the GST-TDS ₹2.5 lakh contract threshold is left to the caller (project flag).
- Expenses have no void reason column; the audit trail records who voided and when.
- Uploads: only expenses take a file in the web app so far (documents, projects and payments could link files later; one file per expense). PENDING uploads never completed are purged after a day (L.4). The virus scan was checked against real ClamAV 1.4.6 on 2026-10-22 (EICAR detected; the test string is only flagged at the start of a file, so it cannot be smuggled inside an uploadable PDF for a QUARANTINED end-to-end check; that path is covered by the fake-clamd tests). Images are not resized or stripped of EXIF location data.
- `auth_sessions` has a `tenant_id` column but no RLS, by design (global table, read only by id / token hash).
- The app role has no privileges on `django_migrations`. `TransactionTestCase`-style flushes (TRUNCATE) will not work as the app role; concurrency tests in step 7 need their own setup/cleanup.
- Until JWT lands (step 5), unauthenticated API calls get 403 `permission_denied`; step 5 makes them 401.
- Compose publishes Postgres on host port **5433** and Redis on **6380**, because native PostgreSQL 17 and Redis Windows services already use 5432 / 6379 on the dev machine.

- Payables (vendor bills, payments to subcontractors) are deferred; expenses track their own payment for now.
- RA bills: credit notes do not reduce the billed quantity (a note may correct a rate rather than a quantity), so over-billing corrected by a credit note still counts against the BOQ; revisit with a quantity flag on note lines. The real-PDF render of the new RA columns is checked only as HTML on Windows (the WeasyPrint test runs in CI / Docker).
- Web: on Windows dev the PDF preview fails (no Pango; run the stack in Docker for PDFs). Editor: the BOQ / catalog item lists are plain selects (fine for hundreds of items; a search box would suit very large BOQs); the refresh cookie is `Secure` only outside dev settings.
- TDS: only income-tax TDS (s.194C) is reconciled; GST TDS (s.51, deducted at payment) is not yet. No import of Form 26AS / TRACES files: certificates are typed in. Expected TDS counts by bill date (credit) and ignores credit notes.
- Retention releases have no PDF / letter yet and no email; a release is not linked to particular bills (retention is pooled per project and book).
- BOQ import only adds items; updating existing items from a file (e.g. revised rates) is not supported. In a dry run, previewed items have null `id` / timestamps although the schema marks them as strings.
- Exports: no export of the GST summary (GSTR-1 covers the same supplies); dates in file names use the server's date (UTC), like the reports' "today". The BOQ export has no project-level header rows (client, contract value): the file name carries the project code.
- GSTR-1: not yet checked by importing into the real GST offline tool / portal (do that with a CA on a real month before relying on it). Not covered: amendments (`b2ba`, `cdnra`…), advances (`at`, `atadj`), e-commerce operators, deemed exports, HSN descriptions; 0 % lines are all reported as nil-rated (the user re-labels exempt / non-GST in the tool); the B2CL limit is ₹1,00,000 for every period (correct from August 2024). The invoice value reported for reverse-charge invoices is the document total (without the tax): confirm with a CA.
- GST: deemed exports, supplies to SEZ for non-authorised operations, and the exact goods vs services place-of-supply rules for exports of goods are not modelled; every overseas client without a project is treated as an export of services.
- Mobile: no sign-up and no 2-step setup in the app (both on the web; an owner without 2-step is sent there). Drafts have no PDF on the phone (preview them on the web). Not yet run on a real phone: checked by Jest on the real routes, by bundling for Android / iOS, and by the API smoke. `npm audit` for mobile gates at `critical`: the high findings today (braces, node-forge, sprintf-js; no fixed release) are Expo CLI, Metro and Jest tooling, not code in the app bundle. `mobile/src/lib/money.ts` and `periods.ts` are copies of the web's (a shared package fights Metro); keep them in step.
- Reports run live SQL per request; fine at current scale, revisit (materialised summaries or caching) if dashboards get slow.
